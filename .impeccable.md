## Design Context

### Users
Atomic Tools is a collection of lightweight, single-purpose web utilities. The primary user is Jason, with occasional sharing when a tool naturally supports it. Each tool should respect the context of use: quick lookup for Wordle Checker, playful creation and sharing for Madlib Maker, focused clipboard conversion for Rich Text Markdown, and dense comparison work for AI Coding Subscriptions. The root index is a launcher, not a marketing site.

### Brand Personality
Direct, practical, and intentionally crafted. Atomic Tools should feel like a private bench of sharp utilities: fast to understand, explicit about what each tool does, and visually deliberate without becoming precious. Individual tools may vary in personality when the job calls for it: analytical for comparison tables, game-faithful for Wordle, expressive for Madlib Maker, and quiet for conversion workflows.

### Aesthetic Direction
Use a compact workshop direction for the overall system: purposeful, low-friction, and built around the task on screen. The visual treatment should come from the tool's domain rather than one universal theme. Data-heavy tools can use refined industrial dashboard patterns. Game tools can borrow recognizable game mechanics when they improve clarity. Creative tools can be warmer and more tactile. Conversion utilities should stay calm, readable, and clipboard-oriented. Avoid landing-page polish, sales copy, decorative gradients, generic SaaS card stacks, and design flourishes that slow down the actual task.

### Design Principles
- Each tool should do one thing well on the first screen; avoid wrapper pages, onboarding copy, and ornamental introductions.
- Match density to the job: comparison tools can be dense, writing tools need room, and quick checkers should minimize steps.
- Keep navigation consistent across tools with a clear return path to the Atomic Tools index.
- Make state visible and inspectable: copied, saved, shortened, filtered, unavailable, inferred, or stale states should be explicit.
- Preserve tool-specific character while sharing basic quality standards for spacing, responsive behavior, keyboard flow, contrast, and readable type.
- Visual emphasis should come from spacing, contrast, type hierarchy, data state, and domain-relevant interaction rather than decoration.
